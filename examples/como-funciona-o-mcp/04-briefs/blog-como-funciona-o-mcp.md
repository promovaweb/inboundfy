# Brief — Como funciona o MCP (blog)

- **Canal:** blog.
- **Formato:** artigo técnico-educativo, 1200-1600 palavras.
- **Público-alvo:** dev backend e arquiteto de software que acompanha o
  blog técnico da empresa e já ouviu falar de MCP, mas não sabe como
  funciona na prática (persona fictícia deste exemplo — em um projeto real,
  aponte para a persona correspondente em `context/publico.md`).
- **Objetivo:** ensinar o leitor a entender o MCP o suficiente para avaliar
  se vale adotar no próprio produto — não é peça comercial, não vende
  nada.
- **Ângulo:** o problema de integração N×M que o MCP resolve, explicado a
  partir de um caso interno reconhecível (Nimbus Copilot), não de teoria
  abstrata.
- **Estrutura persuasiva aplicável:** nenhuma — peça informativa/educativa,
  sem objetivo comercial (ver regra de `ESTRUTURAS-PERSUASIVAS.md`: só se
  aplica a peça com objetivo comercial).
- **Ativos de apoio usados:** teses 1-3, exemplo do Nimbus Copilot,
  primitivas (tools/resources/prompts), analogia do USB-C, FAQ candidato —
  todos de `02-pesquisa-e-ativos/ativos.md`.
- **Restrições de marca:** nenhuma além do padrão do projeto (fictício
  neste exemplo); em projeto real, aplicar `context/marca-voz.md` e
  `context/proibicoes.md`.
- **Restrição de conteúdo específica desta peça:** não afirmar nada sobre
  segurança ou escopo de permissão do MCP sem citar fonte técnica
  confirmada (pendência herdada da fase de pesquisa) — se a fonte não for
  confirmada a tempo, tratar o tópico de forma geral e explicitamente
  remeter à documentação oficial do protocolo, nunca inventar garantia.
- **Critério de pronto:** artigo explica as três primitivas com exemplo
  cada, usa o caso Nimbus Copilot, responde ao menos 3 itens do FAQ
  candidato, e não faz nenhuma afirmação de segurança sem fonte.
